# PR title

fix(sign): sign ETHSIGN over the EIP-191-prefixed digest; add services conformance vectors (v1 + v2)

# PR body

## Problem

`contracts.sign.ecdsa_sign_typed_data` signs the raw EIP-712 digest regardless of the requested `SigningScheme`; `scheme` only labels the result. For `SigningScheme.ETHSIGN` the settlement contract, `cowprotocol/services` (`model::signature::hashed_ethsign_message`) and `@cowprotocol/contracts` `sign.ts` all expect a signature over `keccak256("\x19Ethereum Signed Message:\n32" || eip712_digest)`. An ETHSIGN order or cancellation produced by cow-py therefore recovers to the wrong address and the orderbook rejects it with `WrongOwner`.

Checked against the services-generated conformance fixture from `cowdao-grants/cow-rs` (PR #63, services `df6a14b12eab016f1ae939aa5b666658208b0bc0`): hashing, UID and EIP-712 signing match on all 19 vectors; ETHSIGN signing matched on 0 of 19 before this change.

## Change

- `ecdsa_sign_typed_data` takes `scheme` (default `EIP712`, so existing callers are unchanged). EIP712 signs the digest as before. ETHSIGN signs `encode_defunct(primitive=digest)`. Other schemes raise.
- `sign_order` and `sign_order_cancellations` pass the scheme through.
- `tests/contracts/fixtures/conformance_vectors.v1.json` + `test_conformance_vectors.py`: domain separator, struct hash, EIP-712 digest, UID, EIP-712 signature and ETHSIGN signature for all 19 vectors. 19 fail on `main`, all pass here.
- `tests/contracts/fixtures/conformance_vectors.v2.json` + `test_conformance_vectors_v2.py`: every chain the orderbook runs on (10 domain separators, digests, signatures, UIDs), partially fillable orders, batch cancellations under both schemes, and app-data hash/CID/validity for 7 documents including cow-py's exact default document (asserted byte-identical and equal to `DEFAULT_APP_DATA_HASH`). Generated by the same cow-rs generator from the same services pin (generator change proposed separately to cow-rs).
- `tests/contracts/test_sign.py`: the two existing tests now recover the signer under each scheme instead of checking `v`; new `test_ethsign_order_signature_is_an_eth_sign_of_the_eip712_digest`.
- One strict `xfail` documents a gap rather than hiding it: cow-py has no `OrderCancellation(bytes orderUid)` type (the single-order `DELETE /orders/{uid}` payload); `sign_order_cancellation` signs the batch type, which is correct only for the batch endpoint cow-py wraps.

## Not changed

`swap_tokens` hard-codes EIP712, so the default swap flow was never affected. `sign.py` has five pre-existing `ruff` `UP0xx` findings on lines this PR does not touch; left alone to keep the diff reviewable.
